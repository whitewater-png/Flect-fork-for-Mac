# 18. セキュリティ点検の残課題（0.2.1 時点）

0.2.0 の後に行った全体のセキュリティ点検（3 系統の独立点検）と、その修正の査読（5 回）で見つかった項目のうち、0.2.1 では直していないものの一覧。重大度は点検者の評価。「再現」は実際に再現を確認したもの。

0.2.1 で直したもの（重複削除の自己重複、空フォルダ削除の誤削除、起動引数の `--input` と `--task`、ファイル名の改行、CLI のガード迂回、JAR のサンドボックス解除、削除直前の競合など）は `CHANGELOG.md` と `SECURITY.md` を参照。

## C. 0.2.1 の最終確認で見つかった細かい点

| 重大度 | 項目 | 内容 |
|---|---|---|
| 中（安全側） | FAT/exFAT の 0 バイトファイル | 改名すると iノード番号が変わるため、削除前の改名確認で必ず「変更あり」になる。0 バイトの `.DS_Store` などを含むフォルダは、永久削除の空フォルダ削除で丸ごと見送られる（何も失わない）。0 バイトの重複も同様 |
| 低 | 不要ファイルを先に消したフォルダが残る | 確認の後でサブフォルダに中身が現れると、親から既に消した OS の不要ファイル（`.DS_Store` など）は戻らない。CHANGELOG の「決して」は言い過ぎ |
| 低 | 一時名での確認が ctime を見ない | 改名で ctime が変わるため比較できない。最後の確認から改名までの間に、サイズを変えず mtime を戻す書き換えをされると見抜けない（APFS でも） |
| 低 | `.flect-rm-*` の残り | 名前の衝突やクラッシュで一時名のまま残ったファイルは Finder で隠れ、次の重複削除で普通のファイルとして扱われうる |
| 低 | 表示 | 選んだフォルダがリンクに差し替えられたとき、生のメッセージ「Not a directory (os error 20)」が出る |
| 低 | CI | `--features flect-core/review-seams` で clippy を走らせていないため、検証用の一時停止コードが lint されない |

## D. 原理的に残る限界（SECURITY.md に記載）

- 削除前に付けた一時名を、その瞬間に狙って改名するプロセスには対応できない。
- ゴミ箱モードで、dev・ino・サイズ・両方の時刻を同じに保つ書き換えは見抜けない（FAT は 2 秒、exFAT は 10 ms 単位）。永久削除でも、バイト比較から削除までの一瞬は同様。
- macOS には「この iノードなら削除」という操作がないため、確認と削除の間のごく短い時間は完全には閉じられない。
